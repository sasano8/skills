## 文書の関係と正本

- A は開発手順を B に案内し、編集規約として `plugins/<plugin>/reference.md` を共有定義の正本と明記する。
  そのため共通定義を編集するときは、対象プラグインの README とその正本を追加で開く。
- [README.md](../../../../README.md) は利用者向けの入口。開発の詳細は B、一覧は C、導入の詳細は F に置かれる。
- B「開発環境と普段の流れ」は D、「検証の中身と CI」は E を参照する。
  D・E は手順の実行定義であり、A と異なる規則を独自に決める根拠にはしない。
- プラグイン固有文書の正本・適用範囲は A と各文書の明記を確認する。
  明示されていない優先順位はこのマップでは追加しない。

## 確認範囲と更新

生成に使ったのは上記のローカル文書。外部サイトの最新仕様は今回の生成では根拠にしていない。
他のプラグインの詳細規約をすべて適用するスキルではない。
このファイルは文書の関係と参照先を整理した案内であり、詳細な規則の複製ではない。

生成対象の手順について未取得の必須文書・未解決の矛盾はなし。
文書の移動や節の変更、構成の変更時には参照先と作業の順序を見直す。
詳細ガイドの `docs/` への移動に伴い、開発・導入文書およびプラグイン一覧への参照と文書間の関係を更新。
移動した文書の相対リンクと、参照マップの配置からのパスを確認する手順も反映した。
ガイドの整理も起動対象に含め、ガイド変更時は参照マップ・節名・手順を照合する流れを追加した。
対象指定コマンドは D の現行定義を読む。`PLUGIN` の省略時に特定のプラグインが選ばれるとは扱わない。
