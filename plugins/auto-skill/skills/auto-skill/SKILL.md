# auto-skill — 文書を参照して作業できるスキルを作る

**先に同じディレクトリの [reference.md](reference.md) を読む。** 出力先・正本との分担・
参照マップ・更新方法・検証基準はそこが正本。このファイルには生成の手順だけを置く。

## 1. 入力と対象リポジトリを特定する

依頼から入口文書（ファイル・URL・添付文書）、対象リポジトリ、想定作業を拾う。
指定がなければ作業中のリポジトリを使い、その規約と既存スキルを先に読む。
入口文書が不明なら質問する。読める文書や既存構成の確認は先に進める。
生成物はこのプラグイン自身ではなく、対象リポジトリへ書く。

## 2. 関連文書を読み、関係を整理する

入口から、適用に必要な上位方針・個別ガイド・例外・手順・用語定義をたどる。
リンク先を開かずに内容を断定しない。無関係なサイト全体の巡回はしない。
文書ごとの役割、適用範囲、参照関係、明記された優先順位を整理する。
循環参照は既読として扱い、未取得・矛盾・版の不一致は reference.md の基準で扱う。

## 3. 作業単位にノウハウを構成する

「どの依頼で使うか」「何を先に調べるか」「どの条件で何を判断するか」
「何を実施し、どう確認するか」を、根拠のある順序へまとめる。
文書の目次をそのままスキルの手順にしない。
起動条件と完了条件が異なる作業は分割し、同じ資料を読むだけの理由では細分化しない。
文書の必須事項、推奨事項、例、生成時の推論を区別する。

## 4. スキルと参照マップを生成・更新する

reference.md の出力構成に従い、起動条件を持つ `SKILL.md`、文書関係を記した参照マップ、
ベンダー固有メタデータを作る。詳細な規則を複製せず、必要な作業の直前に正本の該当箇所を
読む手順を組み込む。新規作成と更新の両方で、既存ファイルと利用者の追記を先に確認する。
対象エージェントへの配線は reference.md の方針に従う。

## 5. 参照と代表的な作業を検証する

reference.md の検証基準で、書式・参照・適用条件・根拠・更新差分を確認する。
代表的な依頼を 1 つ選び、生成した手順から必要な正本の箇所へ到達できることを確認する。
文書同士の矛盾や参照切れがある場合も、未解決事項を隠さず判定する。
実際のアプリ変更や外部操作は、スキル生成の検証という理由だけでは実行しない。

最後に生成先、起動条件、正本との分担、検証結果、残る不足、更新した場合の主な差分を短く返す。
