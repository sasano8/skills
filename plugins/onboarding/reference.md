# onboarding 共通リファレンス

`env-bootstrap` / `secret-guard` の 2 スキルが共有する定義。
各 SKILL.md はこのファイルを**原則と進め方の正本として参照する**（同じ内容を各 SKILL.md へ再記載しない）。

対象は**マシン／グローバル設定**（`~` 配下・`git config --global`）。特定プロジェクトの中身は扱わない。

## 原則

- **非破壊** — 自分が張った/書いたもの以外に触らない。既存の実体・他者管理の設定は保持し、警告に留める。
- **冪等** — 何度実行しても同じ状態に収束する。既に入っていればスキップ表示。
- **強制しない** — オンボーディングは**案内**であって強制ではない。勝手に global 設定を書き換えず、
  **まず現状と差分を見せて合意の上で適用**する。
- **判断は持たない** — 「何を・なぜ」の正本は `quality` プラグインの品質規約（例: シークレットは **R15**）。
  ここが持つのは、それをマシンに materialize する**導入手順だけ**。
- **固有パスを焼き込まない** — インストーラ実体・配線先の具体パスは対象 dotfiles リポジトリの関心。
  ここには書かない（汎用スキルにハード参照を持たない＝R11）。

## 進め方（4 段）

両スキル共通のループ。

1. **点検** — 導入状況を確認し「在/不在」を一覧にする。
2. **勧める** — 不在のものに導入コマンドを提示する（OS 別）。値の上書きが要るものは確認してから。
3. **配線** — 合意のものだけ適用する。
4. **検証** — ダミーで効くことを確認 → 後始末。

## 配布方式の選び分け（このプラグインの核）

版管理した設定をマシンへ反映する方式は 3 つあり、**対象がどちらに所有されているかで決まる**。
ここを間違えると、あとから必ず壊れる。

| 対象 | 方式 | 理由 |
| --- | --- | --- |
| **自分が所有し、アプリが書き換えないファイル**<br/>（editorconfig・フックスクリプト・テンプレート） | **symlink** | 実体が repo なので編集が即反映される。dotfiles の本来の強み |
| **アプリが実行時に書き換えるファイル**<br/>（エージェントのユーザー設定など） | **マージ注入**（symlink 不可） | symlink するとアプリの書き込みが repo へ流れ込む。下記「なぜ symlink してはいけないか」 |
| **エージェントのスキル / 拡張** | **配布チャネル**（marketplace 等）<br/>／読まないツールへは symlink | 公式の配布経路がある場合はそれが正路。無いツールへのみ symlink でフォールバックする |

### なぜ「アプリが書き換えるファイル」を symlink してはいけないか

そのファイルは **「あなたが書く設定」と「アプリが所有する実行時状態」が同居する可変ファイル**であって、
版管理対象として設計されていない。symlink すると:

- アプリが状態を書くたびに repo が dirty になる（モデル切替・テーマ変更・拡張のインストール等）。
- **マシン固有の絶対パスが、多マシン共有のリポジトリへ流入する**（他マシンで clone しても解決しない）。
- アプリ側がファイル全体を整形し直すと、意味のある差分が全面書き換えに埋もれる。

Claude Code の場合、`~/.claude/settings.json` は公式ドキュメントが
[**"Do not commit — each developer owns theirs"**](https://code.claude.com/docs/en/settings) と明記しており、
`/config`・`/model`・`/effort`・`/fast` の切り替えやプラグインのインストールで**アプリ自身が書き込む**。
一方 `.claude/settings.json`（プロジェクト）と `managed-settings.json` は**アプリが書かない**ので、
版管理してよい。

したがって、版管理した設定をユーザー設定へ届けたいときの選択肢は次の 3 つ:

| 手段 | 効き方 | 代償 |
| --- | --- | --- |
| **マージ注入**（推奨） | インストーラが、版管理側の「自分が書いたキー」だけを実ファイルへマージする | 双方向同期ではない（再実行で反映） |
| **プロジェクト設定** | repo の `.claude/settings.json` に置いてコミット。アプリは書かない | repo ごとに要る |
| **managed settings** | OS の管理設定パス（`/etc/claude-code/managed-settings.json` 等）。アプリは書かない | 要 root。組織ポリシーの意味論＝プロジェクト側で緩められない |

**マージ注入の実装は対象 dotfiles 側の関心**（ここは方式だけを持つ）。冪等・ドライラン既定・
差分表示してから書く、を満たすこと。

## 注意

- **global 設定は既存を上書きしうる** — `git config --global core.hooksPath` 等は、既に値があれば
  退避/追記の方針を確認してから触る。
- **既存リポジトリの履歴は別問題** — このプラグインが止められるのは*これから*の混入だけ。
  既に commit 済みのものは rotate（失効扱い）→ 履歴 scrub が要る（品質規約 R15 ④）。
- **モジュールは増やせる** — 将来のグローバルガード（lint hook 等）も同じ「点検 → 勧める → 配線 → 検証」で
  スキルを足す。
